# AuditLogs

KQL queries focused on Microsoft Entra ID auditing, administrative activity, privileged access changes, authentication events, password operations, and identity security monitoring using the `AuditLogs` table.

## Available Detections

| Rule                                                                                                                                                                                                              | Description                                                                                                                                                                                                                                                                                                                                                                                                              | Blog                                                                                                      |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| [New Privileged Role Assignment Outside Baseline](https://github.com/ITProfessorCloud/Microsoft-Sentinel/blob/main/KQL/AuditLogs/Analytic%20Rules/New%20Privileged%20Role%20Assignment%20Outside%20Baseline.json) | Detects first-seen privileged Microsoft Entra ID role assignments by comparing the last hour of activity against a 14-day baseline. Enriched with identity context, initiator history, and risk indicators to highlight potentially suspicious privilege escalation activity.                                                                                                                                            | [Read Blog](https://www.itprofessor.cloud/fixing-the-privileged-role-assigned-outside-pim-analytic-rule/) |
| [First Privileged Role Assignment](https://github.com/ITProfessorCloud/Microsoft-Sentinel/blob/main/KQL/AuditLogs/Analytic%20Rules/First%20Privileged%20Role%20Assignment.json)                                   | Detects the first time a user or service principal receives a privileged Microsoft Entra ID role assignment using a 14-day anti-join baseline to suppress previously observed assignee-role pairs. Enriched with identity context and risk indicators to help identify potentially suspicious privilege grants.                                                                                                          | [Read Blog](https://www.itprofessor.cloud/fixing-new-user-assigned-privileged-role-analytic-rule/)        |
| [MFA Denial Composite Risk Score](https://github.com/ITProfessorCloud/Microsoft-Sentinel/blob/main/KQL/AuditLogs/Analytic%20Rules/MFA%20Denial%20Composite%20Risk%20Score.json)                                   | Detects high-risk MFA denial events using a weighted scoring model built from 14 signals, including fraud reports, threat intelligence indicators, password spray activity, burst velocity, unfamiliar countries, and UEBA enrichment. Designed to prioritise MFA denials that are more likely to represent genuine account compromise rather than routine user mistakes.                                                | [Read Blog](https://www.itprofessor.cloud/fixing-the-mfa-rejected-by-user-analytic-rule/)                 |
| [Multiple Password Reset by User](https://github.com/ITProfessorCloud/Microsoft-Sentinel/blob/main/KQL/AuditLogs/Analytic%20Rules/multiple-password-reset-by-user.json)                                           | Detects accounts resetting other users' passwords while excluding self-service password resets and self-password changes. Prioritises activity based on the number of distinct targets, whether the initiator is new to performing password resets, and whether any affected accounts hold privileged roles. Designed to identify account takeover activity, malicious administration, or large-scale lockout campaigns. | [Read Blog](https://www.itprofessor.cloud/fixing-multiple-password-reset-by-user-rule/)                   |
| [Application Consent Risk](https://github.com/ITProfessorCloud/Microsoft-Sentinel/blob/main/KQL/AuditLogs/Analytic%20Rules/application-consent-risk.json) | Detects risky application consent grants by scoring several indicators: access to sensitive OAuth scopes, a privileged consenter, a tenant-wide grant, a consent wave across several users, and apps registered by an in-tenant user. Consents to low-risk scopes never reach scoring, so the everyday openid-profile majority stays silent. Each row is enriched with the consenter roles and department, the session country and risk, and the app creator and age. | [Read Blog](https://www.itprofessor.cloud/fixing-the-rare-application-consent-analytic-rule/) |
| [Account Created From Unfamiliar Domain](https://github.com/ITProfessorCloud/Microsoft-Sentinel/blob/main/KQL/AuditLogs/Analytic%20Rules/account-created-from-unfamiliar-domain.json) | Detects accounts created from a source domain never seen in the tenant, scored by what makes the novelty dangerous: a member account on a newly verified domain, a recent domain or federation configuration change, a lookalike of your own domains, bulk creation from one new domain, a guest inviter, consumer mail sources, and off-hours timing. The baseline is the standing directory and prior creation history rather than sign-ins, so an attacker cannot approve their own domain by authenticating with it. | [Read Blog](https://www.itprofessor.cloud/fixing-the-account-created-from-non-approved-sources/) |
| [Account Created and Deleted in Short Timeframe](https://github.com/ITProfessorCloud/Microsoft-Sentinel/blob/main/KQL/AuditLogs/Analytic%20Rules/account-created-and-deleted-short-timeframe.json) | Pairs a user-account deletion with its earlier creation and surfaces the pair only when the short-lived account did something during its life: it signed in, or it was granted a directory role. A create and delete pair with no in-life activity is treated as lifecycle churn and suppressed. A short lifetime and a single actor running both the creation and the deletion add weight through additive scoring. | [Read Blog](https://www.itprofessor.cloud/fixing-account-created-and-deleted-short-timeframe-rule/) |
| [Account Created or Deleted (Behavioural)](https://github.com/ITProfessorCloud/Microsoft-Sentinel/blob/main/KQL/AuditLogs/Analytic%20Rules/account-created-or-deleted-behavioural.json) | Replaces the static non-approved-initiator list with behavioural detection of account lifecycle abuse. Surfaces a new account granted a sensitive role (backdoor persistence), bulk creation, bulk deletion or deletion of a privileged account, and create and delete churn. Routine bulk provisioning is suppressed by an allowlist of known sync identities, applied only to the volume signals so a privileged follow-on still fires from any initiator. | [Read Blog](https://www.itprofessor.cloud/fixing-the-account-created-or-deleted-by-non-approved-user-analytic-rule/) |
